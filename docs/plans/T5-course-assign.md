- **(i) 응답 매핑·판정 순서.** 경로 자원이 없으면 404 `/problems/not_found`(강의·섹션·세션. 다른 강의의 섹션도 T2a 꼴로 404, service/courses/sections.py:21-25). 본문이 가리키는 자원이 없어도 404 다: 복제 원본 강의 · 커리큘럼 · 배정 강사 · 풀 과정(`missing: [id…]` 칸) · 후보 질의의 `pool_id`. 상태 충돌은 409 `/problems/conflict`: 미승인 강사 배정(`instructor_status` 칸, 결정 viii) · 비활성(사용 중지) 커리큘럼 시작점 · 커리큘럼 소유 강사 미승인(`instructor_status`) · 비활성 풀 과정 고르기(`inactive: [id…]`) · 그 강의에 없는 일차(T2a 결정 v, sections.py:28-30). 본문 모양은 422 `violations[]`: `start` 와 원본 칸의 짝 · `pool_ids` 0개·21개 이상·중복 · 강사 PATCH 의 허용 밖 키(`extra_forbidden`, loc `["body", <키>]`, 결정 xiii). **강사 끝점의 판정 순서는 404 → 403 이다:** 범위 없는 getter(`crud.course.get_course` crud/course.py:27 · `crud.schedule.get_session_and_course` crud/schedule.py:120)로 없으면 404, 있으면 범위(강의는 `course_scope`, 세션은 `instructor_id == 주체`)로 403 — 범위 getter 하나로 404·403 을 섞지 않는다(T4 결정 i 의 함정). 같은 값 배정·같은 값 PATCH 는 200 + audit·outbox 없음(T2a 멱등 규칙) — **단 승인 강사일 때만이다**: 상태 판정(`lock_assignable`)이 같은 값 비교보다 먼저라, 배정된 뒤 정지된 강사를 같은 값으로 다시 주면 409 다(배정 해제 null 은 상태를 보지 않는다). *대안:* 본문 참조가 없을 때 422(loc `["body", <칸>]`).
- **(ii) 경로.** r3 305 의 평면 `/v1/admin/sections/{sid}/sessions:from-pool`·`/v1/admin/sections/{sid}:assign` 을 T2a 의 실제 섹션 경로 꼴(`/v1/admin/courses/{course_id}/sections/{section_id}`, expected_paths 17-19줄(`461e7bd`) · app/endpoints/schedule.py:75-133)로 푼다: `POST /v1/admin/courses/{course_id}/sections/{section_id}/sessions:from-pool` · `POST /v1/admin/courses/{course_id}/sections/{section_id}:assign`. 섹션 조회가 `get_section(session, course_id, section_id)`(crud/schedule.py:84)라 강의 id 가 경로에 있어야 다른 강의의 섹션이 404 로 갈린다. 나머지는 r3 그대로 경로 변수만 `{id}` → `{course_id}`·`{session_id}`: `PATCH /v1/admin/sessions/{session_id}`(T2a 경로, 본문에 `instructor_id` 만 더함) · `GET /v1/admin/courses/{course_id}/assignee-candidates?pool_id=` · `GET /v1/me/courses` · `GET /v1/me/courses/{course_id}` · `GET /v1/me/courses/{course_id}/schedule` · `PATCH /v1/me/sessions/{session_id}`. `POST /v1/admin/courses` 는 경로·끝점 함수(app/endpoints/courses.py:138-155)를 그대로 두고 본문 `start` 만 넓힌다. 새 경로는 7개다. *대안:* r3 글자 그대로 평면 경로(섹션 id 만으로 강의를 찾는다).
- **(iii) 개설 본문 모양.** `CourseOpenIn`(schemas/course.py:79-116)은 **한 모델**로 두고 `start: Literal["blank", "clone", "curriculum"]` + `source_course_id: int | None`(≥ 1) + `curriculum_id: str | None`(1~`POOL_ID_MAX` 자 — T4 상수 80, models/pool.py:61 · 모양 `^[a-z0-9]+(-[a-z0-9]+)*$` — T4 경로 변수 검사 `_TEXT_ID` app/endpoints/pool.py:39·45 와 같은 꼴, 룩어헤드 없어 pydantic 기본 regex 엔진이 받는다)을 더한다. 짝은 `model_validator` 가 본다(blank 는 둘 다 없음 · clone 은 `source_course_id` 만 · curriculum 은 `curriculum_id` 만). 판별 유니온(`Field(discriminator="start")`)은 오류 loc 에 태그가 끼어(`["body","blank","title"]`) 시험 ④가 빨개지므로 쓰지 않는다. 기본 정보·일정 칸(title·client_name·method·hours_per_person·start_on·day_count·day_start·day_end·slot_min·break_min·intro·notice)은 세 시작점 모두 본문이 정한다 — 서버는 원본에서 값을 채우지 않는다(시안의 미리 채움 관리자.html:1588-1593 은 화면 몫이고, 프론트가 원본을 GET 해 채워 보낸다). `open_course(session, body, *, actor, invite_expiry_days) -> (Course, InviteCode)` 서명·반환은 그대로다(⑥). 시작점 분기는 `open_course()` **안에서** 한다: 원본을 먼저 읽고 판정(404·409)한 뒤 → T2a 순서대로 course(커리큘럼이면 `curriculum_src_id` 까지 `insert_course` 에 넘김) → 일차 → 초대코드 → 구조 채움(`service/courses/starts.py`) → audit `course.open`(detail 에 `start`·`source` 두 칸 추가, service/courses/open.py:81-88). 응답 `CourseOpenedOut`(schemas/course.py:181)은 그대로다(복제 결과는 일정표·audit 으로 본다). *대안:* 시작점마다 끝점을 따로 둔다(`POST /v1/admin/courses:clone` 등 — r3 305 와 다르고 단일 진입 시험 대상이 는다).
- **(iv) 복제 범위(시작점 ②).** 복사한다: 섹션(title·sort·description) · 세션(title·description·keywords·minutes·day_no·slot·time_start·time_end·`pool_course_id`·`curriculum_id`·`instructor_id`). 바꿔 넣는다: 세션 `is_open=false`(시안 cloneSections 관리자.html:1569 `open:false`) · 새 강의의 일차 수보다 큰 `day_no` 는 `day_no`·`slot` NULL(「일차 미정」, 관리자.html:1640·1671) · **승인 상태가 아닌 강사의 배정은 NULL**(결정 viii — 복제도 배정이다). 복사하지 않는다: 세션 첨부(기획안 :794 "첨부는 복사하지 않는다(강사가 새 강의에서 다시 확인)" · r3 318) · 일차(본문으로 새로 만든다, T2a `make_days`) · 점심·일차별 시간 · 초대코드(`open_course` 가 새로 발급) · 수강생·세션 토큰 · 보관·상태 · `course.curriculum_src_id`. 새로 붙인다: `pool_course_id` 가 있고 강사가 남은 세션마다 그 강사의 기본 강의안(결정 x · 기획안 :794 "기본 강의안이 있는 과정은 자동 첨부가 다시 일어난다"). 원본 강의는 보관·종료와 상관없이 고를 수 있고(시안은 목록에서 보관을 뺀다 :1605 — 화면 몫) 원본은 바뀌지 않는다. *대안 ①:* 미승인 강사 배정이 하나라도 있으면 409(복제 전체 거절). *대안 ②:* 원본 일차의 시간·점심을 같은 일차 번호에 옮긴다(기획안 :770 "일정은 새 시작일로 같은 일수·시간" 을 서버가 맡음). *대안 ③:* `curriculum_id` 가 있는 세션에 커리큘럼 기본 자료도 다시 붙인다.
- **(v) 커리큘럼 시작점(④).** `lock_curriculum`(crud/curriculum.py:52-66, `461e7bd`)으로 커리큘럼 행을 잠가 읽는다(소유 강사의 차시표 교체와 줄 세움, 결정 xvii) → 없으면 404 → `active` 거짓이면 409(T4 결정 xi "사용 중지" · 기획안 :590) → 소유 강사를 `lock_instructor` → `approved` 가 아니면 409 `instructor_status`(결정 viii — "등록 강사 기본 배정" 이 이 시작점의 뜻이라 조용히 미배정으로 만들지 않는다, 기획안 :770) → 섹션 1개 「전체」(sort 0, 시안 :1670 `name:'전체'`) → `curriculum_slot` 마다 세션 1개(day_no = day · slot = slot · title · description · minutes = 새 강의 `slot_min`(시안 :1670 `minutes:cu.slotMin` — 본문이 커리큘럼 값으로 채워 온다) · `curriculum_id` · `instructor_id` = 소유 강사 · keywords `[]` · `is_open=false`) · 새 강의 일차 밖은 일차 미정 → **커리큘럼 기본 자료(`curriculum_file`)를 모든 세션에 행 복제**(CRS-009 :189 "기본 자료를 각 차시에 복제" · 시안 :1670 `files:cu.attachments` 를 세션마다) → `course.curriculum_src_id` = 커리큘럼 id. 검토(`reviewed`)·공개(`pub`)는 조건이 아니다(시안 :1607 은 미검토도 고르게 한다). *대안:* 소유 강사가 미승인이면 강의는 열고 세션을 미배정으로 둔다.
- **(vi) 풀에서 고르기.** 본문 `{pool_ids: [id] 1~20 중복 없음, day: int | null}`(r3 305 그대로). 고른 순서대로 세션을 만든다: title = 과정 제목 · description = 과정 목표(goal) · minutes = 과정 분(일차에 넣으면 강의 `slot_min`, 시안 :1841-1842) · `pool_course_id` · keywords `[]` · `is_open=false` · `instructor_id` NULL. `day` 가 있으면 그 일차부터 **그 섹션의** 빈 교시에 차례로 넣고 그날이 차면 다음 일차로, 일차가 모자라면 일차 미정이다(시안 scNextSlot :667 · pmgo :1840-1842 · 기획안 :774). 비활성이 하나라도 있으면 409 + `inactive`(아무 행도 쓰지 않음) ③ 새 세션이 FK 로 가리킬 풀 과정 행을 id 오름차순 `FOR KEY SHARE`(결정 xvii) ④ **`lock_course`** ⑤ `section_in_course` 를 한 번 더 부른다 — ① 과 ④ 사이에 섹션 삭제(이제 같은 잠금 아래, 결정 xviii)가 - **(vii) 배정 모델.** 세션마다 담당 강사 1명(`session.instructor_id`, Design 4절 :88 · 기획안 7절 :906 "담당강사" · 요구정의서 :378 "차시 하나의 현재 담당 강사"). 강의 단위 배정 표는 두지 않는다 — 강의의 강사 목록은 세션에서 계산한다(시안 syncInst :1406). 배정을 바꾸는 문은 셋이다: 세션 PATCH `instructor_id`(null 이면 배정 해제) · 섹션 일괄 `:assign {instructor_id}`(그 섹션의 세션 전부, 이미 그 강사인 세션은 건너뜀, 기획안 :775 "이 섹션 전체를 한 강사에게") · 개설 시작점 ②④(결정 iv·v). 배정 해제는 상태를 보지 않는다. **PATCH 에 다른 칸(제목 등)과 `instructor_id` 가 함께 오면, 잠금 안에서 PATCH 전체를 검증·적용한 뒤 배정을 기록한다**(codex 1차 #5): `lock_course` → (새 강사면) `lock_assignable` → T2a 칸 검사(일차·교시·예외 시각)와 칸 적용 → 강사 바꾸기·기본 강의안 → audit·outbox. 그래서 audit detail 과 알림 본문의 세션 제목은 이번 PATCH 가 준 새 제목이다(옛 순서는 배정 스냅샷을 먼저 찍어 옛 제목을 남겼다). 일괄 응답은 200 `{section_id, instructor_id, changed: [session_id…], materials: int, skipped_missing: int}`(`SectionAssignOut` 에 `skipped_missing` 칸을 둔다 — codex 2차 #5, 계약 시험 `test_assign_section_bulk` 가 HTTP 본문에서 키와 정수를 단언). 섹션 일괄은 `lock_course` 를 기다린 사이 그 섹션이 지워졌으면 **잠근 뒤 `section_in_course` 를 다시 불러 404** 다(`changed: []` 200 이 아니다 — codex 2차 #6, 결정 i 의 "없는 자원 404", 풀에서 고르기 결정 vi ⑤ 와 같은 꼴). *대안:* 강의당 강사 1명(`course.instructor_id`) — Design 0007 행·기획안 7절이 세션 단위라 고르지 않는다.

name) -> tuple[asyncio.Event, asyncio.Event]`**(held, release) — `module.name` 을 감싸개로 바꾼다. 첫 호출만 진짜 함수를 끝까지 부른 뒤 held 를 켜고 release 를 기다리며, 둘째 호출부터는 그대로 통과한다(B 도 같은 함수를 부를 수 있다). **`_race_paused(factory, engine, held, release, hold, contend)`** — A 를 `_commit_after` 태스크로 띄우고 `asyncio.wait_for(held.wait(), 5)` 로 장벽을 기다린다(A 가 장벽 전에 끝나거나 5초가 지나면 "장벽에 닿지 않음" 으로 실패) → B 태스크 → `_waits_on_lock` → `_blocked_on` → `release.set()` → 둘을 `asyncio.gather(…, return_exceptions=True)` 로 15초 안에 모은다. finally 에서 release 를 켜고, 끝나지 않은 태스크를 cancel 한 뒤 `await asyncio.gather(*남은 태스크, return_exceptions=True)` 로 끝나기를 기다리고 나서야 세션을 닫는다 (T2b `tests/integration/test_db_concurrency.py:118-122` 와 같은 꼴 — 장벽·단언이 실패해도 DB 작업이 남은 채 세션 정리·끝의 TRUNCATE 로 넘어가지 않게, codex 3차 #2).
