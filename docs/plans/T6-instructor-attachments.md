- **(i) 응답 매핑·판정 순서.** 강사 끝점은 T5 강사 끝점 꼴(T5 결정 i)대로 **범위 없는 getter 로 404 → 그다음 403** 이다: 세션은 `crud.schedule.get_session_and_course`(crud/schedule.py:121-137, `ff16a42`)로 없으면 404, `session.instructor_id != 주체` 면 403(남의 세션·미배정 세션). 첨부는 새 `crud.attachment_edit.get_with_session` 으로 없으면 404, 그 세션이 내 것이 아니면 403. 강의 읽기는 T5 `mine.course_for`(service/courses/mine.py:89-96 — get_course 404 → `in_scope` 403). **경로 id 는 T5 `IdPath`**(app/endpoints/assign.py:42, `1cca8ca` — `Annotated[int, Path(ge=1, lt=DB_ID_LIMIT)]`, `DB_ID_LIMIT = 2**63` schemas/course.py:65)를 쓴다: 2**63 이상은 DB 를 치지 않고 422 `["path", <이름>]`(type `less_than`), 표현 가능한 없는 id(2**63-1)는 404 다(T5 codex 구현 리뷰 MAJOR — 그대로 두면 BIGINT 범위 오류로 500). 상태 충돌 409 `/problems/conflict`: 세션당 첨부 상한(`limit` 칸, 결정 iv) · link 가 아닌 첨부에 `url` PATCH · link 첨부의 `:replace`. 본문 모양 422 `violations[]`: 폼 `title`·`file` 모양 · 모르는 확장자 · 확장자와 첫 바이트 불일치 · 교체가 종류를 바꿈(loc `["body","file"]`) · JSON 본문 허용 밖 키(`extra_forbidden`, loc `["body", <키>]`) · null 금지 칸. 411·413 은 T2b 꼴이다(Content-Length 없음 411 · 상한 + 1MiB 초과 413 · 종류별 실제 크기 413). 501 은 둘이다: 저장소 미구성 `/problems/not_configured`(T1·T2b 그대로) · HTML 패키지 열기 `/problems/not-implemented`(결정 ix). 파일 업로드 판정 순서: 401 → 403(InstructorCaller) → 422(경로 id 범위) → 404(세션) → 403(내 세션 아님) → 409(상한, 잠그지 않은 미리 셈) → 411 → 413(Content-Length) → 400(깨진 폼, Starlette) → 422(title·file 모양) → 501(저장소) → 422(머리 8KiB 로 확장자·첫 바이트) → 413(그 종류 상한) → 바이트 쓰기 → `lock_course` → 다시 읽어 404·403·409 → 201. JSON 본문 끝점(`:link`·PATCH)은 FastAPI 가 경로·본문을 핸들러 전에 검증하므로 401 → 403 → 422 → 404 → 403 → 409 순이다(T5 `PATCH /v1/me/sessions/{session_id}` 와 같다). *대안:* 남의 세션도 404(존재를 숨김) — T5 강사 끝점의 404 → 403 과 갈려 고르지 않는다.
- **(ii) 경로.** r3 306 의 강사 끝점을 T5 꼴 경로 변수로 푼다: `GET·POST /v1/me/sessions/{session_id}/attachments`(GET 은 r3 에 없는 메서드 〔정함〕 — I4 오른쪽 목록(기획안 :604)이 `href`·`origin` 이 있는 내 세션 첨부를 읽어야 하는데, T5 상세 `/v1/me/courses/{course_id}` 는 첨부 **수**만 주고 T5 시험이 그 응답에 `href` 가 없음을 단언한다) · `POST /v1/me/sessions/{session_id}/attachments:link` · `PATCH·DELETE /v1/me/attachments/{attachment_id}` · **`POST /v1/me/attachments/{attachment_id}:replace`**(r3 에 없는 경로 〔정함〕, 결정 vii) · `GET /v1/me/courses/{course_id}/portal` · `GET /v1/me/home` · `GET /v1/me/courses/{course_id}/invite-code` · `GET /v1/me/courses/{course_id}/invite-code/notice`(r3 "(+notice)", T2a 관리자 경로 꼴) · `GET /v1/me/courses/{course_id}/enrollments`. 새 경로는 9개다(T5 76 → 85). 경로 id 는 전부 `IdPath`(결정 i, T5 `my_courses.py` 가 `from classfit.app.endpoints.assign import IdPath` 로 들이는 꼴). `:replace` 를 따로 둔 까닭: 교체는 바이트 쓰기라 411·413 미리 거르기와 폼 파싱이 필요하고, 제목·순서 PATCH 는 JSON 이라 한 경로에 두 본문 꼴(multipart·JSON)을 섞으면 끝점이 Content-Type 으로 갈라 읽고 OpenAPI 를 손으로 적어야 한다. 동작 접미사는 경로 규칙(Design 5절 2 :106 "동작은 `:접미사`")이고 T2a `invite-code:reissue` 와 같은 꼴이다(Starlette 는 `{attachment_id}` 경로가 메서드에서 갈리면 다음 경로를 찾는다 — T2a `courses/{course_id}` 와 `courses/{course_id}:archive` 전례). *대안:* r3 글자 그대로 `PATCH` 가 multipart(파일 교체)와 JSON(제목·순서)을 둘 다 받는다(새 경로 8개, 84줄).
- **(iii) 업로드 종류·검증.** 강사는 파일 넷과 링크를 올린다(기획안 I4 표 :608-612 · MAT-001 :210). **종류는 파일 이름의 확장자로 정하고**(시안 kindOf 강사.html:1132 와 같은 방식), 첫 바이트가 그 확장자의 모양과 맞아야 한다. 받는 확장자는 기획안 표 + `.jpeg` 하나다: pdf `.pdf`(`%PDF-`) · office `.pptx`·`.docx`·`.xlsx`(zip 머리 `PK\x03\x04`)·`.csv`(머리에 NUL 없음) · html `.zip`(`PK\x03\x04` 또는 빈 zip `PK\x05\x06`) · image `.png`(`\x89PNG\r\n\x1a\n`)·`.jpg`(`\xff\xd8\xff`)·`.webp`(`RIFF` + 8~11바이트 `WEBP`) — 여기까지가 기획안 :609-612 이고, `.jpeg` 는 기획안 표에 없지만 시안 kindOf(강사.html:1132)가 받고 `.jpg` 와 같은 JPEG 라 같은 줄로 받는다. 대소문자는 보지 않는다. content_type 은 받은 값이 아니라 확장자 표의 값으로 고정한다(T2b 결정 viii 꼴 — `application/pdf` · OOXML 셋 · `text/csv` · `application/zip` · `image/png`·`image/jpeg`·`image/webp`). 폼은 `title`(필수, T2b `Title`) · `description`(선택) · `file`(필수, 파일 이름이 있어야 한다)이고 `kind` 칸은 받지 않는다(와도 T2b `_form_fields` 꼴로 아는 글자 칸만 읽어 무시한다). **끝점은 파일 머리 8KiB 만 먼저 읽어 판정**하고(`await upload.read(8192)` → `classify`), 통과하면 `await upload.seek(0)` 뒤 **그 종류 상한 + 1바이트까지만** 읽는다 — 모양이 틀린 파일이나 이미지 자리의 큰 파일을 100MB 까지 메모리에 올리지 않는다(service 는 받은 바이트로 다시 판정한다). link 는 `:link` JSON `{title, url, description?}`(T2b `http_url` schemas/attachment.py:39 — http·https, 2048자). zip 은 풀지 않고 보관만 한다(NFR-006 :405 압축 해제 제한·진입 파일은 열기 기능과 함께, r3 §7-5). 판정은 순수 함수 `service/rules/attachment.py::classify(filename, head) -> (kind, content_type)` 하나다(단위 시험 표). `PDF_MAGIC` 도 그 모듈로 옮기고 T2b `service/files/attachments.py` 가 다시 내보내 T3 documents.py:21 · T4 pool_files.py:29 의 import 는 그대로 둔다(매직 원본 한 곳). *대안 ①:* 시안 목록(`.ppt .doc .xls .hwp .hwpx .gif .svg`, 강사.html:1132)까지 — 옛 오피스·한글은 OLE 머리라 매직 표가 늘고, svg 는 스크립트를 담을 수 있어 1차에 받지 않는다. *대안 ②:* T2b 처럼 폼 `kind` 를 받고 확장자와 맞는지 본다.
- **(iv) 상한.** 크기는 종류별 설정 칸이다(Design 5절 20 :124 — 기본값이 있어 `missing()` 밖): pdf 는 기존 `attachment_pdf_max_mb`(50, core/config.py:59) · 새 `attachment_office_max_mb`(50) · `attachment_zip_max_mb`(100) · `attachment_image_max_mb`(10)(기획안 :609-612 · MAT-002 :211 · r3 306 — 크기 값은 정본에 있다). Content-Length 미리 거르기는 넷 중 가장 큰 값 + 1MiB(종류는 폼을 읽어야 안다)이고, 실제 크기는 그 종류 상한으로 413 이다(결정 iii 의 머리 판정 뒤). **개수는 세션당 20개**(`ATTACHMENTS_MAX` 〔정함〕). **이 값의 정본 근거는 없다** — 기획안·요구정의서·r3 어디에도 세션당 첨부 개수 상한이 없다(2026-10-22 `grep` — "개까지"·"개수 상한"·"첨부 상한" 0줄). 기본으로 두는 까닭은 T4 선례(`POOL_FILES_MAX` 20, models/pool.py:57 — 소유자당 파일 행 상한, T4 결정 viii)와 같은 값으로 한 세션의 행이 끝없이 늘지 않게 하려는 것뿐이다. 상한은 강사 넣기(파일·링크)에서만 건다 — 세는 대상은 그 세션의 첨부 전부(관리자 것·사본 포함)이고, 바이트를 읽기 전에 잠그지 않고 한 번(빠른 409), `lock_course` 뒤에 다시 한 번(정답) 센다. 관리자 넣기(T2b)와 T5 기본 강의안 사본은 상한을 걸지 않는다(관리자는 예외 문이고, 사본은 빈 세션에만 붙는다 — 그래서 한 세션이 20개를 넘은 채 있을 수 있고, 그때 강사 넣기는 409 다). 넘으면 409 + `limit: 20`. 교체는 개수가 그대로라 세지 않는다. *대안 ①:* 크기 상한을 설정 칸 대신 상수로. *대안 ②:* 관리자 넣기도 같은 개수 상한(T2b `add_*_attachment` 에 잠근 뒤 셈을 더한다 — T5 정적 시험의 호출 순서 단언은 그대로 성립). *대안 ③:* **개수 상한 없음**(1차 생략 — 정본에 없으므로). 그러면 시험 둘(`test_attachment_cap_20_409` · `test_attachment_race_cap_two_adds_one_409`) · 정적 단언 ④ · 대조 실험 둘(13·14) · 증명 표 두 행(12·16)이 빠지고, 넣기 경로의 잠금 누락은 행동 시험 `…_reassign_then_write_403`·`…_session_removed_then_write_404` 가 그대로 잰다.
- **(v) 쓰기 판정 — 배정 강사만, 세션의 첨부 전부.** 넣기·고치기·바꾸기·순서·지우기는 그 세션의 현재 담당 강사(`session.instructor_id == 주체`, T5 0007)만 한다(요구정의서 권한 매트릭스 :99 "본인 차시 업로드·정렬·삭제" · COM-002 :145 · UAT-005 :423 · 기획안 I4 :598). 강사 상태는 다시 보지 않는다: 배정은 승인 강사만 받고(T5 결정 viii), 정지는 산 세션을 폐기해 옛 토큰이 401 이며(T3 결정 v · app/deps.py:8-9), 승인 → 대기·반려 전이는 없다(T5 결정 ix). 담당 강사는 그 세션의 첨부 **전부** — 관리자가 올린 것과 기본 강의안 사본(`origin` 있음)도 — 고치고 지운다(기획안 I4 :602 "나가는 데이터 Attachment 추가·순서·삭제" · :616 사본이 첫 번째지만 순서 ▲▼ 를 둔다 · 시안 delAtt 강사.html:1138 이 종류를 가리지 않는다). 사본을 지우면 그 사본의 `stored_file` 행만 지워지고 원본 파일 행·바이트는 남는다(같은 sha 를 원본 행이 가리켜 gc 가 남긴다 — 요구정의서 :392). *대안 ①:* `origin` 있는 사본은 강사가 못 지운다(409). *대안 ②:* 쓰기마다 `lock_instructor` 로 `approved` 를 다시 본다(잠금 순서 course → instructor 는 T5 ③ → ④ 라 성립하지만, 지금 전이로는 배정된 강사가 미승인일 길이 없다).
- **(vi) 파일 열람 판정 — `OWNER_KINDS["session_attachment"]` 의 강사 갈래.** `_session_attachment`(crud/scope.py:137-153, `ff16a42`)는 지금 관리자 참 · 수강생은 같은 강의 ∧ `is_open` · 그 밖 거짓이다(:143-144 · 독스트링 :13-14 "T6 이 강사를 넓힌다 … 강사는 T5 의 강의 범위 안이어도 거짓"). 강사 갈래를 더한다: **첫 WHERE `course_scope(강사)`**(T5 갈래 :74-80 — 세션 하나라도 배정된 강의) ∧ 그 첨부 id ∧ (**`session_scope(강사)`** — 새 범위 함수, 그 세션이 내 세션 · 결정 xxii ∨ **그 세션 `is_open`**). 내 세션 첨부는 공개 전에도 연다(올린 사람이 확인한다). 같은 강의의 남의 세션은 수강생에게 열린 것만 연다 — 강사 포털 미리 보기(결정 xiii ①)의 열린 카드 `href` 가 강사에게도 열리고, 남의 공개 전 초안은 닫힌다(기획안 :577 "다른 강사 세션은 흐리게"). 기획안 :617 "해당 강의에 등록된 수강생과 강사·관리자만 열 수 있다" 를 강의 범위로 지킨다. 관리자 참(audit 없음 — T4 결정 ix 꼴, 강의안은 서류가 아니다)과 수강생 갈래는 그대로다. 새 owner_kind 는 없다 — 강사 첨부도 `session_attachment` 행이다(plan.md T6 메모 "강사 첨부의 owner_kind 판정은 따로 정한다" 의 답. `instructor_document` 처럼 관리자에게 거짓인 종류가 아니다). **T5 단언 한 줄을 뒤집는다**(착수 조건 ⑤ — `tests/integration/test_db_assign.py:223` 와 주석 :213). 그 사례(X 의 열린 내 세션 첨부)는 두 갈래 어느 쪽으로도 참이라 강사가 자기 첨부를 여는 어떤 판정에서도 뒤집힌다. 같은 커밋에서 `crud/scope.py` 독스트링 :13-14 와 `service/courses/mine.py` 독스트링 :6 의 "강사에게 거짓이다, T6 몫" 을 고친다. *대안 ①:* 내 세션 첨부만 연다 — 포털 미리 보기의 남의 열린 카드 `href` 가 강사에게 403 이 된다(미리 보기에서 그 `href` 를 빼면 `PortalOut` 이 수강생 것과 달라진다). *대안 ②:* 범위 강의의 첨부 전부(`is_open` 무관, 기획안 :617 글자 그대로) — 남의 공개 전 초안이 열린다. *대안 ③:* 강사가 올린 파일에 새 owner_kind(예 `instructor_attachment`)를 주어 `session_attachment` 판정과 T5 단언을 그대로 둔다 — **고르지 않는다**: Design 4절 owner_kind 목록(:95)이 바뀌고, 같은 `session_attachment` 행인데 올린 사람에 따라 파일 종류가 갈려 관리자·수강생 판정이 두 함수에 겹치며, T2b 소유자 삭제(`_delete_where` crud/attachment.py:140-157)가 `owner_kind == 'session_attachment'` 로만 파일 행을 지워 강사 파일 행이 남는다(Design 5절 11 위반 — 고치려면 T2b crud 도 바뀐다). T5 결정 xii 가 이미 "T6 이 강사를 넓힌다" 로 이 변경을 예고했다.
- **(vii) 교체 — 같은 행의 파일만 바꾼다.** `POST /v1/me/attachments/{attachment_id}:replace`(multipart `file` 하나): 첨부 id·`sort`·`title`·`description` 은 그대로이고, 바이트 쓰기 → `lock_course` → 다시 읽기 → 새 `stored_file`(owner = 같은 첨부 id, 새 key) → `file_id` 를 새 행으로 → **옛 `stored_file` 행을 같은 트랜잭션에서 지운다**(기획안 :618 "첨부를 교체하면 이전 파일은 바로 지운다" · 8-3 :951 · T3 서류 교체 service/files/documents.py:43-56 와 같은 순서) → audit `session_attachment.update` fields `["file"]`. 옛 key 의 행이 없으니 옛 `href` 는 404 다(파일 끝점 app/endpoints/files.py:53-57 — r3 167 "교체 뒤 옛 href 404" · MAT-003 :212 "교체·삭제 시 기존 열람 권한을 제거"). 지울 "옛" 행은 **잠근 뒤 다시 읽은** `file_id` 다 — 두 교체가 겹치면 뒤 요청은 앞 요청이 바꾼 파일 행을 지운다(행동 시험 ④). 옛 바이트는 참조 0 이면 유예 뒤 gc 몫이고, 다른 행(기본 강의안 원본·다른 사본)이 같은 sha 를 가리키면 남는다. **같은 종류만 받는다** — 확장자로 정한 종류가 그 첨부 `kind` 와 다르면 422 `file`(바이트를 쓰기 전). link 첨부의 교체는 409 다(주소는 PATCH `url`). **바꾸면 `origin` 은 NULL** — 내용이 더는 기본 강의안 사본이 아니다(T5 결정 xi 의 "원본 기본강의안 여부"). link 사본의 주소를 PATCH 로 실제로 바꿀 때도 같은 규칙이다(결정 viii, codex 1차 #4). *대안 ①:* 새 첨부 행을 만들고 옛 행을 지운다(id·자리가 바뀌어 클라이언트가 다시 읽는다). *대안 ②:* 종류를 바꿀 수 있다(pdf → pptx). *대안 ③:* 바꿔도 `origin` 을 남긴다.
- **(viii) 순서 — PATCH `position`.** `PATCH /v1/me/attachments/{attachment_id}` 의 JSON 본문은 `{title?, description?, url?, position?}` 이다(`extra="forbid"` — `kind`·`file_id`·`sort`·`origin`·`session_id` 는 422 `extra_forbidden`, T5 `MySessionPatchIn` 꼴). `position` 은 그 세션 첨부 목록((sort, id) 순)에서 0부터 센 자리이고 목록 길이를 넘으면 마지막으로 줄인다. 잠근 뒤 그 세션의 첨부를 populate_existing 으로 다시 읽어 새 차례로 `sort` 를 0..n-1 로 다시 매긴다(한 요청 한 트랜잭션이라 ▲▼ 를 `sort` 값 두 번의 PATCH 로 맞바꿀 때의 엇갈림이 없다). 첫 번째가 카드 「강의안 열기」의 기본 대상이다(기획안 :616 · MAT-003 :212) — 포털·목록은 이미 (sort, id) 순이다(crud/attachment.py:121·133-135). `url` 은 link 만(아니면 409)이고, **정규화한 주소(T2b `http_url` schemas/attachment.py:39 — 앞뒤 공백 제거·제어 문자·scheme 검사)가 지금 값과 실제로 다르면 `origin` 을 NULL 로 한다** — 기본 강의안 사본 링크의 주소를 바꾸면 더는 사본이 아니다(결정 vii 의 교체와 같은 규칙, codex 1차 #4). 정규화한 값이 지금 값과 같으면 바뀐 칸이 없어 `origin` 은 그대로이고 audit 도 없다. 제목·설명·자리만 바꾸면 `origin` 은 그대로다(가리키는 내용이 같다). audit fields 에는 `["url"]` 만 싣는다(`origin` 비움은 그 결과). `title`·`url`·`position` 의 null 은 422, `description` 의 null 은 지운다. 같은 값이면 200 · audit 없음(T2a 멱등 규칙). 응답은 그 첨부 하나(`MyAttachmentOut`). *대안:* `POST /v1/me/sessions/{session_id}/attachments:reorder {ids: [...]}` 로 한 번에(경로 +1).
- **(ix) html 열기 501 범위.** 1차는 보관만이다(r3 §7-5 :202 · ADR-003 결정 7 :25 · Design 3절 :74 · intent :57 · DEC-011 :454). `GET /v1/files/{key}` 가 범위 판정(403)을 지난 뒤 그 `stored_file.content_type` 이 HTML 패키지 고정값 `application/zip`(결정 iii)이면 **501 `/problems/not-implemented`** 다(`AppError(501, …, type=…)`, app/errors.py:38 — 도메인 `NotConfigured` 의 `/problems/not_configured` 와 갈린다). 주체를 가리지 않는다(관리자·담당 강사·수강생 모두). 판정 순서는 401 → 501(저장소) → 404 → 403 → **501(HTML 패키지)** → 200 이라 남의 강의 수강생은 403 을 받는다(존재를 흘리지 않는다). 첨부 응답의 `href` 는 다른 종류처럼 준다(`AttachmentOut.href: str` 이 필수 칸이라 바꾸면 T2b·T5 단언이 깨진다). 판정 자리는 owner_kind 가 아니라 content_type 이라 다른 소유 종류에 zip 이 생겨도 같은 501 이다. *대안 ①:* 관리자와 그 세션 담당 강사는 zip 을 내려받고(200, 내려받기 헤더), 수강생만 501. *대안 ②:* HTML 첨부의 `href` 를 null 로(T2b `AttachmentOut` 모양·T5 키 집합 단언을 고친다).
