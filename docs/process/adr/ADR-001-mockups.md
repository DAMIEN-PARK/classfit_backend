# ADR-001: 시안 HTML 은 참고 자료로만 쓴다

- 상태: 승인 (2026-10-21, r3 플랜 승인 · 승인자 `DAMIEN-PARK`)
- 출처: r3 §4 "ADR-001 시안 · ADR-004 공개홈" 행 · 부록 A6 · §2 가정 1·4 · §3 결정 동인 ① · §7 4번 · r1 C 추천
- 구현 지점: 모든 태스크(OpenAPI 가 계약) · T2a·T9a(시안 JS 로 golden 추출)
- 검토 기록: [시안 검토](../research/2026-10-21-mockup-review.md)

## 결정

1. 시안 3종(관리자·강사·학습자 HTML)은 화면 참고 자료로만 쓴다. 서빙하지 않고, 상수를 API 호출로 치환하지 않는다(r3 부록 A6 C1).
2. 1차 산출물은 API·DB·OpenAPI·계약 시험이다. OpenAPI(`/v1/openapi.json`)가 나중 프론트의 계약이 된다.
3. 시안 JS 의 순수 함수(`scTime`·`scMakeDays`·`calc`)는 golden 기대값의 출처로 쓴다. 추출 스크립트는 숫자·시각만 대조 대상으로 남기고, 이름은 가명 토큰으로 바꾼다([Design](../2026-10-21-phase1-backend-design.md) 5절 17).
4. 시안과 기획안이 어긋나면 기획안 v3 가 기준이다(r3 §2 가정 1, 파이프라인 v3 끝 문장).
5. `시안/` 폴더는 커밋하지 않고 미추적으로 둔다. 검토한 판은 [spec.md](../spec.md) 1절 색인의 sha256 으로 고정한다.

## 동인

- 화면 소비자가 없다. 프론트 구현 주체가 정해지지 않았다(r3 §3 동인 ①, §2 가정 4).
- 시안 파일은 각각 938~2237줄이고, localStorage 키로 파일끼리 동기화한다(강사.html:705 · 관리자.html:1148). 화면을 그대로 띄우려면 치환이 곧 프론트 재작성이다(부록 A6 C2).
- 시안은 판정을 화면 상수·수동 토글로 한다. 서버가 판정할 규칙 13가지가 따로 있다(검토 A4).
- 시안 자료에 실명처럼 보이는 자료가 있다(관리자.html:1050, r3 §7-4). 커밋하면 기록에 영구로 남는다.

## 대안

| 대안 | 버린 이유 |
|---|---|
| C2 FastAPI 정적 서빙 + 상수 치환 | 이해관계자에게 시안 화면을 그대로 보여 줄 수 있다. 그러나 파일당 938~2237줄 단일 파일이고 localStorage 로 서로 묶여 있어 치환은 프론트 재작성이다. 백엔드가 버릴 코드를 떠안는다(부록 A6) |
| C3 별도 프론트로 바로 넘긴다 | 역할 분리는 맞다. 그러나 넘길 주체가 없다(부록 A6) |
| 시안 폴더를 커밋해 정본으로 쓴다 | 기획안이 제품 정본이고 시안은 참고다(가정 1). `기획/`·`시안/` 을 커밋하면 18MB 가 기록에 영구로 남고, 시안에는 실명처럼 보이는 자료가 있다(§7-4) |

## 고른 이유

- 백엔드가 API·DB 에 집중한다. 응답 모양은 OpenAPI 로 고정되어 프론트가 정해져도 바뀌지 않는다(r1 C 추천: 지금은 C1, C3 로 넘어갈 준비).
- 시안의 계산을 golden 으로 옮기면 화면 없이도 "시안과 같은 값"을 시험으로 잴 수 있다(r3 §3 원칙 ④).

## 대가 (결과)

- 1차에는 시연할 화면이 없다(부록 A6 C1 단점).
- 시안과 기획안의 데이터 계약 차이 11건은 API 쪽에서 정한 이름·값으로 푼다. 나중 프론트는 시안이 아니라 OpenAPI 에 맞춘다(검토 A2).
- 시안의 동작 중 기획안과 다른 것(예: 학습자 강의 전환)은 시안 UI 수정 대상으로 남는다([요구정의서](../../requirements/2026-10-21-요구정의서.md) DEC-004).

## 후속

- 프론트 주체가 정해지면 이 ADR 을 다시 본다(r1 I 후속).
- `기획/`·`시안/` 커밋 여부는 사용자 결정을 기다린다(r3 §7-4).
- T2a: golden 추출 스크립트와 일정 golden 시험. T9a: 점수 golden 시험(Design 부록 A).
