# ADR-002: 수강생 세션은 강의 하나에 묶는다

- 상태: 승인 (2026-10-21, r3 플랜 승인 · 승인자 `DAMIEN-PARK`)
- 출처: r3 §4 "ADR-002 학습자" 행 · §3 결정 동인 ③ · §1.1 ④ · §2 가정 6 · 변경 기록 N9·N10 · 부록 F
- 구현 지점: T1(`auth_session`) · T2b(입장·재입장·포털·`learner`·`enrollment`)

## 결정

1. 수강생 토큰은 강의 하나에 묶인다. 다른 강의는 그 강의의 코드 + 이메일로 다시 들어온다. T1 의 `auth_session` 은 수강생 행이면 `course_id` 가 있어야 한다(CHECK, 부록 C 0002).
2. 같은 이메일은 같은 `learner` 로 묶는다(기획안 5-4). `learner` 는 이메일만 갖고 이름을 갖지 않는다. 표시 이름·부서는 강의마다 `enrollment` 에 적는다.
3. 입장 실패 이유는 기획안 P3 대로 보인다(없는 코드·형식 오류·종료·만료·정지·정원·준비 중).
4. 재입장은 그 강의의 현재 코드 + 등록 이메일이면 정지·만료·정원·종료와 무관하게 된다(§2 가정 6, 기획안 P3 "코드 만료돼도 기존 등록자는 재입장"에서 파생).
5. 수강생 세션 수명은 1일이다(§1.1 ④ 승인자 답). T1 설정 기본값으로 쓰고, 설정 칸 하나로 바꾼다.

## 동인

- 가장 새로운 위험은 비밀번호 없는 수강생과 파일 열람이다(§3 동인 ③, Architect r1-1).
- 학습자 사칭: 남의 이메일로 새 강의에 등록한 사람이 그 이메일의 다른 강의에 들어가면 안 된다(부록 F 첫 행).
- 이름 덮어쓰기: 같은 이메일로 다른 강의에 다른 이름을 등록해도 남의 다른 강의 명단이 바뀌면 안 된다(부록 F 둘째 행, N9).
- 교육장 공용 PC: 세션이 길면 다음 사람이 앞사람 세션을 쓴다(§1.1 ④).

## 대안

| 대안 | 버린 이유 |
|---|---|
| 토큰 하나로 여러 강의를 오간다(기획안 L1 "내 강의 전환" 그대로) | 사칭 등록 한 번으로 같은 이메일의 다른 강의까지 열린다. 강의 범위 세션이 이 위험의 완화다(부록 F) |
| `learner` 가 이름을 갖고 강의마다 덮어쓴다 | 공격자 이름이 남의 다른 강의 명단에 뜬다(N9) |
| 입장 실패 이유를 숨긴다 | 기획안 P3 가 이유를 보이도록 정했다. 노출을 수용하고 이 ADR 에 기록한다(부록 F) |
| 세션 수명 30일 | 종료 후 복습은 편하지만 공용 PC 에서 위험하다. Critic r2 가 1일을 보류해 §1.1 ④ 로 승인자에게 물었고, 답은 1일이다(N10) |

## 고른 이유

- 교차 강의 접근이 구조로 막혀 시험 하나로 고정된다: `test_cross_course_portal_403`(T2b).
- 이름 분리도 시험 하나로 고정된다: `test_enrollment_name_isolated`(T2b).
- 입장 규칙은 기획안 P3 표를 그대로 따르므로 화면이 생겨도 판정이 바뀌지 않는다(P3 7행 → 시험 9건, T2b).

## 대가 (결과)

- 기획안 L1 "내 강의 전환"은 강의마다 재입장이 된다. "같은 이름으로 이어서"는 같은 강의 재입장에만 적용된다.
- 코드를 가진 사람은 입장 실패 이유로 강의 상태를 안다. 코드 공간은 32^6 이고 대응은 재발급이다(부록 F).
- 정지로 기존 등록자를 막지 못하므로 코드 유출 대응은 재발급뿐이다.
- 종료 강의에서 등록 여부가 드러난다.
- 수명이 1일이라 종료 후 복습 때마다 재입장한다.

## 후속

- T1: `auth_session` 의 learner ⇔ `course_id` CHECK, 수명 기본값 1일(부록 J T1).
- T2b: P3 시험 9건 · 재발급 2건 · 교차 강의 403 · 이름 비덮어쓰기 · 동시성(정원·재발급).
- 관련 열린 질문: 수강생 데이터 보관 기간(§7 6번)은 이 결정과 별도로 정한다.
