# Intent: BCTONE 강사관리 플랫폼 백엔드 (ClassFit)

- 종류: product
- 원 작성자: DAMIEN-PARK · 초안: Claude · 상태: approved
- 승인: DAMIEN-PARK 2026-10-22 (가지 T0b-sdlc-okf 의 승인 빈 커밋 `approve: T0b` c19aadd·e9998db, 트레일러 `Approved-by: DAMIEN-PARK`. 내용의 출처인 r3 플랜은 2026-10-21 에 승인됐다)
- 대체: 없음

## 문제

관찰된 사실만 적는다. 출처는 기획안 v3 01·9-1 절이고, 9-1 은 2026-09-22 실측이다.

1. 현행 AI Lab 은 강사들이 Claude Code 로 손으로 짜서 운영한다. 홈·커리큘럼·고객사 포털을 강사 개인이 코드로 관리한다(기획안 01, 9-1).
2. 현행 고객사 포털 하나가 공통교육 2세션과 부서 8섹션, 세션 카드 63장으로 되어 있다. 새 고객사 포털은 코드로 다시 만든다(9-1, 1-2 "1차 목적").
3. 현행 AX 커리큘럼은 정적 HTML 한 장에 144과정이 인라인 JSON 으로 들어 있다(9-1). 과정을 고치려면 그 파일을 고친다.
4. 매 수업마다 강사에게 강의안과 서류(이력서·자격증/경력증명·강사 서약서)를 다시 요청한다. 이 일을 없애는 것이 플랫폼을 만드는 이유 중 하나다(1-2 "자료·서류 요청 대체").
5. 고객사는 공용 계정으로 들어온다. 기획안은 이것을 강의별 초대코드로 바꾼다(9-2).
6. 제안서를 손으로 다시 만든다. 진단 결과와 과정 데이터가 한곳에 없기 때문이다(1-2 "2차 목적").
7. 이 저장소에는 아직 백엔드 뼈대만 있다. 표는 감사 로그 하나(마이그레이션 0001)이고 끝점은 상태 확인뿐이다. 화면 시안 3종은 상수와 시뮬레이션으로 동작한다(기획안 10절).

## 바라는 결과

1차 백엔드(T1~T9b)가 병합되면 아래가 계약 시험으로 확인된다. 화면은 1차 범위가 아니므로 확인은 API 호출과 시험으로 한다([feature intent](intents/2026-10-21-phase1-backend.md)).

1. 관리자가 코드를 고치지 않고 강의 1건을 개설하고, 섹션·세션을 넣고, 초대코드를 발급한다. 고객사가 하나 늘 때 바뀌는 것은 DB 행뿐이고 코드 변경은 0줄이다(기획안 원칙 1, T2a).
2. 수강생이 그 코드와 이메일로 입장해 포털에서 세션 카드를 보고 첨부 강의안을 연다. 비밀번호는 없다(원칙 2, T2b). 기획안 P3 입장 판단표 7행이 시험 9건으로 하나씩 녹색이다(r3 §6 E-10).
3. 다른 강의의 수강생은 그 강의의 포털과 파일을 열지 못한다(403, T2b `test_cross_course_portal_403`).
4. 강사가 가입하고 관리자가 승인하면 그 강사가 배정 후보에 오른다. 배정된 강사는 자기 세션의 설명·키워드·공개·첨부만 고친다(원칙 3·13, T3·T5·T6).
5. 관리자가 만족도 설문을 강의에 배포하고, 강사와 관리자는 응답을 개인과 연결하지 않은 결과로 본다(원칙 9·10, T8).
6. 관리자가 사전진단을 방문 작성하거나 링크로 받아 확정하고, 점수가 시안의 산식과 같은 값으로 나온다(원칙 7·8, T9a golden).
7. 교육 문의가 접수되고 담당자 알림이 outbox 에 쌓인다. 실제 발송은 1차에 하지 않는다(T9b, [ADR-003](adr/ADR-003-external-ports.md)).
8. 1차 마지막 병합(T9b) 뒤 r3 §6 수용 기준 E-1~E-14 의 명령이 전부 기대 출력을 낸다.

## 영향 받는 사람·시스템

| 대상 | 영향 (기획안 1-3) |
|---|---|
| 관리자(비씨티원) | 강사 승인, 강의 개설·배정, 초대코드 관리, 사전진단, 만족도 배포를 플랫폼에서 한다 |
| 강사 | 가입 후 승인을 기다린다. 승인 전에도 프로필과 "내 과정"을 쓴다. 배정된 세션에 강의안을 붙인다 |
| 수강생 | 6자리 코드와 이름·이메일로 들어온다. 포털에서 강의안을 열고 만족도에 답한다 |
| 기업 담당자 | 로그인하지 않는다. 관리자가 만든 회사 카드와 PDF 로만 만난다 |
| 현행 AI Lab | 버리지 않고 데이터로 옮긴다(기획안 9절, 이관은 1차 백엔드 밖) |
| 공개홈 | 별도 트랙이다. 화면은 보류하고 API 만 만든다([ADR-004](adr/ADR-004-public-home.md)) |
| 나중의 프론트 | 1차의 소비자는 계약 시험과 OpenAPI 다. 시안은 참고 자료로만 쓴다([ADR-001](adr/ADR-001-mockups.md)) |

## 제약

- 기획안 03 운영 원칙 13개가 화면·기능보다 앞선다(기획안 03 머리말). 코드로 지키는 자리는 [spec.md](spec.md) 2절 정책 대조표에 있다.
- 스택은 FastAPI · SQLAlchemy 2.0 async · psycopg 3 · Alembic · PostgreSQL 17 이다. 금지 의존성은 CLAUDE.md Rules 와 [spec.md](spec.md) 2절에 있다.
- 외부 의존(파일 저장·메일·PDF·HTML 패키지)은 포트 뒤에 둔다. 1차는 로컬 디스크·outbox·501 이다([ADR-003](adr/ADR-003-external-ports.md)).
- 새 의존성과 판 올리기는 승인자의 승인이 먼저다. 1차에 필요한 것은 pyyaml(dev, T0b)·argon2-cffi(T1)·python-multipart(T2b)이다(r3 §1).
- 시험·시드 자료는 가명이다. 실고객사명은 쓰지 않는다(원칙 12, r3 §2 가정 5).
- 승인자는 1인(DAMIEN-PARK)이다. 계획 승인과 병합은 사람이 한다([agent.md](agent.md)).
